# 自动化基础学习台

一个本地优先、无需登录的 F28335/CCS 基础学习执行台。它把学习内容收窄到一条主线，帮助你每天快速确认：

1. 今天只学什么；
2. 今天最多做哪三件事；
3. 用什么证据证明已经掌握；
4. 下次从哪里继续。

Markdown 和 Git 仍是长期内容的原件；这个站点负责组织当日行动、记录过程并导出可归档的学习日志。

## 本地运行

环境要求：Node.js `>=22.13.0`。

在项目目录中执行：

```powershell
npm install
npm run dev
```

终端会显示本地访问地址。日常开发和交互检查请使用 `npm run dev`。

生产构建检查：

```powershell
npm run build
```

Windows 使用当前锁定的 vinext `0.0.50` 时，`npm start` 的静态资源路径存在已知兼容问题，不能作为可靠的本地生产预览。Windows 请继续使用 `npm run dev` 检查页面，以 `npm run build` 判断生产构建是否成功；`npm start` 仅用于已经确认兼容的平台。

其他检查命令：

```powershell
npm test
npm run lint
```

## 本地数据与自动保存

- 学习状态保存在当前浏览器、当前站点来源的 `localStorage` 中，不需要账号或后端。
- 编辑后会自动保存，界面会显示“保存中”“已保存”或“保存失败”。
- 更换浏览器、切换站点域名、使用隐私窗口或清除站点数据时，本地记录不会自动迁移。
- 升级、清理浏览器或迁移设备前，请先下载一份 JSON 备份。

## JSON 备份与恢复

在“学习记录”页的数据管理区域：

1. 选择“备份 JSON”，保存当前完整学习状态。
2. 恢复前建议再下载一份当前状态作为保险。
3. 选择要导入的 JSON 文件。
4. 阅读覆盖提示并确认后，才会用备份内容完整替换当前状态。

导入不是合并操作。应用会先校验 `schemaVersion`、记录结构和引用关系；文件无效时不会部分覆盖现有数据。JSON 文件可能包含学习问题、证据和备注，请按个人资料妥善保存。

## 对接 Obsidian 每日日志

在“学习记录”页下载当天的 Markdown 文件后：

1. 找到浏览器下载的 `YYYY-MM-DD.md`；
2. 将它移动到学习仓库或 Obsidian 仓库的下列位置：

   ```text
   logs/daily/YYYY-MM-DD.md
   ```

3. 在 Obsidian 中打开检查，再按你的 Git 工作流提交。

导出的文件使用 UTF-8、普通 Markdown 标题和简洁 YAML，不依赖 Obsidian 社区插件。内容包括日期、当前主题、主问题、任务结果、掌握证据、错误或疑问、相关文件或命令，以及“下次第一件事”。

## V1 已实现

- 五个固定入口：今日学习、学习路线、知识与开发板、学习记录、以后再学；
- 今日唯一主问题、最多三项任务、上次遗留和下次第一件事；
- 六阶段 F28335/CCS 学习路线、前置关系和完成标准；
- 基础知识卡、开发板信号路径和按需电路知识；
- “未接触 → 能识别 → 能解释 → 能应用”掌握等级；
- “能应用”必须关联完整证据的约束；
- 错误、疑问、待复习项和学习证据记录；
- 浏览器本地自动保存及文字状态反馈；
- 完整 JSON 备份、校验和覆盖恢复；
- Obsidian 兼容的每日 Markdown 下载；
- 电脑和手机上的响应式核心流程。

## V1 明确不做

- 登录、账号、服务器、数据库和多人协作；
- AI 问答、自动生成课程和实时同步；
- Obsidian 专用插件或双向同步；
- PDF、文献库和复杂资料管理；
- 串口、MQTT、OPC UA 或真实设备控制；
- PLC、PID、电机控制和大型仿真；
- 独立的 C 语言复习阶段，以及超出当前 F28335/CCS 主线的课程。

这些内容被刻意延后，避免学习入口演变成复杂平台。V1 的目标是完成“选择今天的重点 → 执行任务 → 留下证据 → 明确下一步”这一条可验证闭环。
