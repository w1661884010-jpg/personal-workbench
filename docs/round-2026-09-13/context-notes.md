## 2. 数学错误对照（原文 — 问题 — 修正 — 依据）

### C1–C4　波形变换 x(2−t) 的操作顺序

- **原文**（小节4 detail[1]，courses.js:744）："把它写成 −(t−2)：先右移 2，非零区间变到 2≤t≤3；**再关于纵轴翻转**，端点互换，区间变成 1≤t≤2"
- **问题**：把 x(t−2) 关于纵轴翻转得到的是 x(**−t−2**)，支撑 [−3,−2]，**不是** x(2−t)。结果 [1,2] 对，但**推导过程错**——按它写的操作根本得不到 [1,2]。
- **修正**：先翻转 x(t)→x(−t)（支撑 [−1,0]），再右移 2 得 x(−(t−2))=x(2−t)（支撑 [1,2]）。交叉验证：置 0≤2−t≤1 直接解得 1≤t≤2。
- **依据**：定义代入 + 支撑区间计算。
- 同步落点：小节4 正文、例题「矩形脉冲的镜像变换」两步、检验 check-11 解析、大纲文档第 4 小节。

### C5　拉普拉斯例题 x(t)=e^(3t)u(−t)

- **原文**（例题「判断拉普拉斯变换能否退化为傅里叶变换」步骤 3 + 答案）："收敛域位于极点左侧且**不包含虚轴** σ=0，因此傅里叶变换**不存在**"／"（信号在 t→−∞ 方向**指数增长**）"
- **问题**：两处都错。X(s)=1/(3−s)，ROC 为 Re{s}<3，**包含虚轴**（σ=0 < 3）；且 t→−∞ 时 e^(3t)→0，信号**衰减**、有界。
- **修正**：X(s)=1/(3−s)=−1/(s−3)，ROC Re{s}<3（含虚轴）⇒ 傅里叶变换存在，X(jω)=1/(3−jω)。
- **依据**：∫_{−∞}^{0}e^{(3−s)t}dt 收敛 ⟺ Re(3−s)>0 ⟺ Re{s}<3；虚轴落在该半平面内。
- **注**：同章另一处"e^(2t)u(t) 的 ROC Re{s}>2 不含虚轴 ⇒ FT 不存在"是**对的**，勿连带改动。

### C6　单边 / 双边拉普拉斯共用一张公式卡

- **原文**：公式卡为单边 `X(s)=∫_{0^-}^{∞}x(t)e^{−st}dt`，但同一节正文讨论左边信号与不同 ROC。
- **问题**：左边信号、双边 ROC 属**双边**变换范畴；单边变换的用途（含初始条件的微分方程）未标注，两者混用。
- **修正**：公式卡改双边定义 `X(s)=∫_{−∞}^{∞}x(t)e^{−st}dt`；变量表注明"单边形式积分下限取 0⁻，用于含初始条件的微分方程，不用于判别左边信号"。

### C7　矩形卷积的峰值

- **原文**（小节5 detail[1]）："结果是底宽 2、峰值 1 的三角形，**峰值等于两个脉冲面积之积** 1×1=1"
- **问题**：一般规则是**峰值 = min(w₁,w₂)**；"面积之积"是**输出总面积**（= w₁·w₂），不是峰值。单位高度、等宽时两者数值巧合相等（都为 1），把巧合写成了规则。
- **修正**：峰值 = min(w₁,w₂)，输出总面积 = w₁w₂；等宽 1×1 只是两者恰巧同为 1 的特例。
- **依据**：分段卷积；且站点 `app.js` 的 `analyticConvolution` 早已实现 `peak = min(w1,w2)`——代码与正文原本互相矛盾。

### C8–C9　阶跃响应

- **原文**（例题「与冲激、阶跃卷积分别得到什么」答案）："h=u(t) 时 y(t)=∫（−∞ 到 t）x(τ)dτ，也就是输入的滑动积分，**即该系统的阶跃响应**"
- **问题**：把两个不同对象混为一谈——(a) 冲激响应 **h=u(t)** 的系统对**任意输入**的输出，是输入的滑动积分；(b) **阶跃响应**是**输入取 u(t)** 时的输出 g=h*u。对本例的 h=u(t)，阶跃响应应是 (u*u)(t)=t·u(t)，不是 ∫x。
- **修正**：拆成两句分别陈述；并在小节6 的 g(t) 表达式上写明上下限 g(t)=∫_{−∞}^{t}h(τ)dτ。

## 3. 本轮**自行发现**的两个真问题（不在任务单里）

### R1　窄屏 390px 整页横向溢出 163px（本轮引入的回归）

- **现象**：打开第 1 章后 `document.scrollWidth = 553`（视口 390）；停在绪论时正常。3010 同场景正常，故确认为本轮改动引入。
- **定位过程**：逐层隐藏 bisect → 隐藏 `#lessonResources` 后恢复 390 → 逐个卡片测 `width: min-content` → 命中例题「判断拉普拉斯变换能否退化为傅里叶变换」的最小内容宽度 **477px**（`X(s)=∫_{−∞}^{0}e^(3t)e^(−st)dt=∫_{−∞}^{0}e^((3−s)t)dt` 这段不可断的数学串）。
- **根因**：栅格列是 `1fr`（= `minmax(auto,1fr)`），其自动最小尺寸由最长不可断内容决定 → 整列被撑到 553px，`.chapter-col` 跟着变宽，页面出现横向滚动。
- **修正**：① `.lesson { overflow-wrap: anywhere }`（必要时允许在词内断开）；② 该例题步骤拆句并加空格，缩短不可断串。
- **依据**：实测 553 → 390；3010 对照 390。
- **测试补强**：原窄屏用例**只检查停在绪论的首屏**，所以这个回归没被发现。已改为**逐章打开后**再断言无横向溢出。

### R2　窄屏下公式卡被裁切（看不全）

- **现象**：390px 时 `time-basic` 内容 406px / 可见 286px，`time-singular` 461/286，`frequency` 301/286（后者是既有卡，非本轮新增）。
- **根因**：`aligned` 公式不换行，`.math-formula` 只能内部横向滚动 → 读者看不到右侧。
- **修正**：把过长的对齐行拆成更短的行（`time-basic` 3 行→4 行、`time-singular` 4 行→6 行）+ 窄屏 `.math-formula .katex { font-size: .92em }`。
- **结果**：8/8 张卡在 390 / 760 / 1440 三档均不裁切（`scrollWidth == clientWidth`）。
- **测试补强**：加断言——任一 `.math-formula` 的 `scrollWidth > clientWidth + 2` 即失败。
